# 私人学习助手：构想与 MVP 基线

版本：0.1 · 2026-10-15

## 一、产品目标

做一个理解个人目标、记得学习经历、能够持续调整教学方式的私人学习助手。用户可以碎片化学习，同时始终看得到学习主线。学习成果以独立的学习树保存，既能回看，也能留作纪念。

## 二、已经确定的设计

### 1. 从自由对话建立学习需求

- 用户先自由描述，不要求一开始就填写完整表单。
- 用户基本完成叙述后，Agent 整理已知需求，再针对缺失信息追问；选项与自由补充并存。
- 需要了解：已有基础、学习目的、目标程度、难度、详细度、时间安排和其他备注。
- 学习方式可组合，例如先打比方，再讲概念，最后看例题；不把偏好固定成单一学习类型。
- 用户可以随时提建议、改变节奏、讨论学习方法，助手据此逐步调整。

### 2. 以目标驱动组织学习

- 主要入口：用户提出目标，助手搜集信息、组织内容并建立路线。
- 补充入口：用户提供教材、课件或笔记，助手围绕资料组织学习。
- 先给出简洁的整体路线和主要知识点，不预先生成全部卡片。
- 约十张待学习卡片作为滚动余量；随着进度、问题和偏好变化补充、调整。

### 3. 每个目标一棵学习树

- 不同学习目标分别成树，相关知识可以跨树联系。
- 开始时展示整体路线的轮廓，之后逐步点亮。
- 节点表示主要知识点，章节对应主要分支。
- 沿主线推进，点亮后续内容；从某个知识点深入探索，可以长出新分支。
- 保留实际学习路径、笔记和问答，完成后仍然可以回看。
- 点亮依据本次约定的完成标准；“看过”“掌握”“跳过”分别记录，跳过不自动等于掌握。

### 4. 轻量分页卡片与随时问答

- 每页只承担少量内容，宁可多一些页数。
- 内容形式仅限文字和图片；首版不生成动画或动态演示。
- 概念、注释、类比、案例、例题、延伸和思考问题可拆为不同页面，用户按需展开或跳过。
- 一个知识点可有多张卡片，卡片与树节点不要求一一对应。
- 学习过程中保留对话窗，支持知识提问、学习方法讨论和教学反馈。
- 支持自主浏览和更多引导两种方式，允许切换。

### 5. 个人资料库贯穿所有学习

- 自动整理个人背景、长期目标、兴趣、学习偏好和学习经历。
- 记录学过什么、进度、理解依据、曾经的问题和未解决的问题。
- 用户明确表达的信息与助手暂时推断的信息分别记录；保留适用情境并允许纠正。
- 用户可查看、修改、删除记录。
- 后续学习结合旧知识、旧案例和旧疑问；不能仅凭浏览记录认定已经掌握。

## 三、首版 MVP 建议范围

先跑通一次完整的个人学习循环：

自由描述 → 整理与补问 → 确定目标及偏好 → 建立学习树 → 生成首批短卡片 → 阅读、提问与反馈 → 点亮节点或增加支线 → 保存进度和个人记忆 → 再次进入后继续学习。

建议保留四个主要区域：学习树列表、当前学习树、卡片与对话、个人资料库。

首版优先支持单人使用和持久保存，先验证流程；多用户协作、分享社区、复杂奖励体系、动画演示不进入首版。

## 四、暂未确定，但不继续扩大讨论的事项

| 事项 | MVP 暂定处理 / 后续方向 |
| --- | --- |
| 产品载体 | 已选择本机浏览器应用，先验证个人使用的完整循环 |
| 模型提供方及 API | 预留可替换接入；真实接入需要提供方、模型和凭据 |
| 信息搜集与来源核验 | 保留来源字段；联网检索能力需要单独选定并接入，不将模型生成内容标为已检索资料 |
| 上传资料 | 已确认支持方向；复杂文件解析可在后续迭代补充 |
| 内置 skills 与 Agent 分工 | 先形成需求整理、路线规划、卡片生成、问答、记忆整理等清晰职责，后续再完善自动调度 |
| 难度与掌握判断 | 首版采用事前约定、用户反馈和简单问答，后续增加更细致的判断依据 |
| 跨树关联 | 首版记录可追溯的关联，后续优化自动发现与调用 |
| 图片来源与生成 | 支持静态图片展示；图片获取方式、版权和自动生成流程后续确定 |
| 长期记忆更新 | 先支持查看和人工修正，逐步完善冲突、过期信息和情境差异的处理 |

## 五、MVP 验收标准

1. 能新建学习目标，整理自由叙述并补充必要信息。
2. 能看到整体树轮廓，打开节点并阅读少量内容组成的多页卡片。
3. 能主动完成、跳过或返回节点，状态含义清楚。
4. 能围绕当前节点问答，选择把探索加入分支。
5. 退出后重新打开，学习树、进度、问答和资料仍在。
6. 能查看和纠正个人记忆，后续学习可调用相关记录。
7. 演示数据、真实模型生成、已验证来源和待接入能力有明确区分。

## 六、本轮边界

以上“已经确定的设计”来自对谈；“MVP 建议范围”和“暂定处理”属于实现提议，可以在试用后调整。当前不继续扩充功能清单，以跑通核心循环作为下一阶段目标。
