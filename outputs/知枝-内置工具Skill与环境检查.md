# 知枝：内置工具、Skill 与环境检查

> 这是整合前检查快照；本轮已处理的差距及实际验收请看《知枝-开工准备与验收》。保留本文用于追踪最初缺口。

日期：2026-10-23｜对照：MVP 策划案 v3.0｜方式：静态源码、依赖、环境与 APK 内容核对。

## 1. 结论

**尚未齐备。当前是“原知枝的基础学习功能＋独立 Pi 最小验证＋完整设计文档”，不是新版逻辑已全部嵌入的应用。**

原应用位于 outputs/learning-grove，应用 ID 为 app.zhizhi.personal；Pi 验证应用位于 outputs/pi-mobile-probe，ID 为 app.zhizhi.piprobe。二者没有自动合并。已交付的两份 APK 中 app.js 均与各自当前源码/构建产物一致；原应用的 mobile-service.js 和打包的四份教学规则也一致。

“文件存在”“模型可调用”“已打包”“端到端验收”是四种不同状态。策划案或本会话可用的搜索工具，不会自动成为 APK 的工具。

## 2. 实际已嵌入什么

| 能力 | 原知枝应用 | Pi 验证应用 |
| --- | --- | --- |
| Pi Core | package.json 未声明，业务中未使用 | 1.4.0 已安装并打包，实际工具循环已检查 |
| 模型可调用工具 | 业务动作由程序执行，未注册为 Pi 工具 | 仅 read_learning_context 一个工具 |
| 本地读写 | IndexedDB 学习状态，保存后返回成功 | 独立 IndexedDB 偏好、验证结果与报告 |
| 模型请求 | Personal.generate，传 system/topic，读取回复正文 | PiProbe.complete，保留工具消息和完整回复的适配 |
| 密钥 | 安卓原生加密保存，设置与连接测试入口 | 独立原生加密保存，不共享原应用 Key |
| 教学规则 | intake、roadmap、cards、tutor 四份 | 硬编码的最小验证指令，无完整教学 skill 包 |
| 取消与请求上限 | 未形成新版统一任务机制 | 最小验证有取消、超时、请求及工具次数上限 |
| 导出 | JSON 学习档案；未实现导入恢复 | 验证报告；不是正式学习档案恢复 |

原生插件的 complete、setKey、cancel 等方法是平台能力；不能把它们都算成模型已注册工具。验证器的 persist 由程序提交，也不是额外的模型保存工具。

## 3. Skill 清单及差距

原知枝 skills/*.md 与 static/skills/*.md 四份文件逐一相同，APK 内也有四份文件，打包链基本一致。但内容仍是旧规则：

| 需要的规则 | 现状 | 与新版差距 |
| --- | --- | --- |
| 主 Agent 通用规则 | 没有正式 Pi 主 Agent 规则入口；验证器只有最小提示词 | 需要当前任务、通用边界、分阶段加载与输出契约 |
| 需求分析 | intake.md 已有 | 一轮最多三项补问；尚无完整信息状态、约定版本与接受状态 |
| 框架规划 | roadmap.md 已有 | 固定 3—4 章、每章 2—3 节；缺节点价值、前置性质及材料对应 |
| 卡片生成 | cards.md 已有 | 固定三张，含思考题；不符合新版完整节点、按需分页、主线不出题 |
| 主动答疑 | tutor.md 已有 | 已有当前卡片与相关记录上下文，但无新版内容版本、反馈动作及策略提交契约 |
| 资料检索与知识整理 | 未建立正式规则 | 需要缺口、读取依据、来源状态及冲突出口 |
| 节点页序与质量检查 | 缺正式规则与业务发布门槛 | 现有字段检查不等于七项内容质量检查 |
| 学习结算 | 未建立 | 问答提取少量记忆不等于按活动与事件范围结算 |
| 独立加强学习 | 未建立 | 旧完成/跳过动作不是题目、判据、证据和通过标记 |
| 学科规则与教学方法 | 未形成正式可加载资料包 | 数学、历史等要求目前主要写在设计文档中 |

prepare-mobile.py 当前只复制上述四份规则。新增文件还须纳入资源清单、加载、校验及 APK 同步；仅在目录放入 Markdown 不会自动生效。规则应按任务加载，不是一次塞入全部文本。

## 4. 业务工具与程序机制缺口

下列是需要实现的能力分类，名称为建议，不能当作已有 API：

| 能力 | 当前基础 | 尚需补齐 |
| --- | --- | --- |
| 读取约定与节点上下文 | 有树、目标、偏好、节点 | 正式契约、版本、信息来源及 Pi 读取适配 |
| 读取相关学习经历 | 已有文字匹配的本地问答检索 | 有效性筛选、情境、连续性、来源引用与删除失效 |
| 读取学习材料 | 验证器只有固定函数材料 | 实际材料读取、位置记录、要点关联与缓存 |
| 按缺口检索外部资料 | 未接入 | 选定真实检索/读取实现及其配置；不能靠提示词获得联网能力 |
| 生成节点计划与正式卡片 | 有初版生成和保存 | 必要要点、页序、检查、内容版本与发布门槛 |
| 反馈与路线修订 | 可改偏好、手动分支/连接 | 直接做/告知/先建议的动作契约与可撤回版本 |
| 活动结算与个人策略 | 有原始问答、少量提取记忆 | 活动边界、事件水位、去重、合并、冲突与策略更新 |
| 加强学习 | 有浏览和手动状态 | 独立题目、判据、答案、目标版本与证据 |
| 生成任务与补货 | 有约十张余量的初版 refill | 当前＋下一节点、优先级、取消、过时结果、短事务与可靠重试 |
| 档案恢复 | 有导出 | 导入校验、合并/覆盖、版本迁移与升级验收 |

原业务队列把网络生成与状态操作放在同一串行处理路径；新设计要求阅读与短写入不等长模型请求，因此还需拆分任务执行与提交，不能只替换模型调用函数。

原应用只有状态整体 revision，尚不能替代约定、节点、正文、策略与任务的版本关联。记忆增删改已经存在，但删除一条摘要尚无完整的衍生记录失效与禁止重新提取机制。

## 5. 环境检查

### 开发与构建环境

| 项目 | 检查结果 |
| --- | --- |
| Git、Node.js、npm、Python | 可用 |
| Pi 验证项目依赖 | npm ls --depth=0 通过；Pi Core/pi-ai 1.4.0、TypeBox、Capacitor、esbuild 齐备 |
| JDK | 工作区工具缓存内 OpenJDK 21.0.12.1 可直接运行；未加入全局 PATH |
| Android SDK | 工作区内有 API 36、Build Tools 35/36、platform-tools 与 Gradle 缓存 |
| Pi 验证构建配置 | 依赖和 local.properties 存在；已有成功 APK |
| 原知枝构建配置 | 当前未安装项目 node_modules、未生成本机 local.properties；是需恢复的构建配置，不影响已打包 APK 使用 |

工具位于 work/pi-probe-tools。原项目 Windows 构建入口对 .tools 路径有自己的约定；正式接入时需统一或明确平台构建配置，不能因为另一项目编译过就视为本项目可直接同命令构建。

### 用户手机运行环境

已安装 APK 不需要用户安装 Node、Python、JDK、SDK 或 Git。用户需要受支持的安卓/WebView、模型网络和自己的 Key；真实账户与手机当前 Key 状态无法由工作区静态检查确认。本轮不读取、索取或迁移用户密钥。

新资料检索服务的选择、访问通道及可能的授权/限额尚未配置；首个正式节点可以先用实际提供的固定材料，避免它阻塞基础教学链验证，但不能宣称自动检索已完成。

## 6. 补齐顺序

1. 以 Pi 验证路径接入正式业务，建立统一上下文、结构化结果和受控提交；保留原数据与应用身份。
2. 改造 intake、roadmap、cards、tutor，补知识整理、质量检查、结算规则及首个学科参考；同步业务校验，不只复制文件。
3. 用真实固定材料跑通一个节点：需求、路线、定义/例子/区分、主动问答、反馈、结算与重开。
4. 加入真实资料读取/检索、来源注册、滚动任务、版本失效及记忆治理。
5. 单独实现加强学习和档案导入、升级保护，完成对应验收。通用 skill 自动升级、多 Agent 与新 UI 仍后置。

这些是检查后的缺口与实施建议，本轮未自动安装或补齐。
