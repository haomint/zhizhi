## 规则准备与功能启用是两回事

以下已写成可加载规则并进入 APK，但还没有完整业务触发器和提交校验：

- `knowledge`：缺口、材料要点、来源支持范围。
- `page-plan`：按目标安排页序和要点覆盖。
- `quality`：目标、前置、定义、例子、连贯、来源、负担七项语义检查。
- `settlement`：新增事件范围、证据、策略建议。
- `reinforcement`：独立加强问题、判据和证据。

数学/历史规则作为参考已准备，学科路由尚待接入。现在卡片的程序门槛只检查结构、节点归属、讲述类型和定义/例子位置；不能把它当成语义审核、事实核验或学习效果验证。

## 推荐开工顺序

1. **真实材料单节点闭环。** 先选“函数是什么”等稳定基础主题，提供可实际读取、有位置标识的材料。挂接知识整理、页序和质量规则；保存节点版本、来源 ID 和检查结果。主线完整讲述，不强制回答。
2. **结算与个人适配。** 建立事件 ID/范围和去重提交；验证“以前读过高数”只作为相关联系，不自动等于掌握；修正与删除应影响后续生成。
3. **阅读连续性。** 实现当前/下一节点预生成、取消和恢复；保留本轮短事务和过时结果保护。
4. **检索与独立加强、导入。** 在前面闭环稳定后分别接入，不一次扩展所有模块。

首个闭环完成门槛：材料真实；定义与例子正确；节点有来源与质量记录；问答绑定当前页；反馈能改变下次讲法；退出重开能接续；失败不污染已有资料。通过这些再扩大主题数量。

## 签名与安装限制

最终检查发现旧知枝 0.6.1 签名（SHA-256 以 5e9a9dd3 开头）与当前保留的 Pi 验证签名（以 45820da6 开头）不同。未找到旧签名私钥。因此本次 debug 包使用 `app.zhizhi.personal.integration`，名称“知枝·整合验证”，可与旧知枝并行安装；不要求卸载旧版。新包不会自动继承旧密钥或学习记录，当前也没有导入恢复。

主应用 ID 仍留在源码默认配置中；未来正式覆盖升级需要找回旧签名并补齐数据升级验收。此项不影响当前独立验证与开发，但不能标作已完成覆盖升级。
