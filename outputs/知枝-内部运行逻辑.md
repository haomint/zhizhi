# 知枝内部运行逻辑 · 评审基线

日期：2026-10-23。本文依据现有构想、安卓 0.6.1 源码与推进记录整理；用于确定后续开发规则。本次交付为设计文档，未修改应用或安装包。“当前”表示源码已有实现，“确定规则”表示本次提出供验收的运行约定，不能据此宣称已实现。

## 1. 核心决策

知枝围绕一个循环运行：明确学习目标 → 建立路线 → 准备近期内容 → 阅读与对话 → 记录学习证据和反馈 → 调整下一步 → 下次接续。

每个目标是一棵学习树，树管理路线；节点管理知识点；卡片承载短内容；问答记录具体交互；个人资料库跨树保留有来源、有情境的长期信息。阅读过程自然推进，只有需要判断掌握或改变路线时才增加必要交互。

执行上采用一个业务调度层、四类教学规则和一个模型通道。业务层决定何时调用、读取哪些记录、校验并保存哪些字段；模型负责归纳、规划、编写与答疑。当前四份 skills 是提示词规则，不是四个独立 Agent，也没有自主工具调用平台。现阶段继续沿用这种单流程架构。

## 2. 运行结构与职责

| 层次 | 职责 | 当前安卓实现 |
| --- | --- | --- |
| 界面 | 输入目标、卡片阅读、提问、查看树与资料 | static/app.js |
| 业务调度 | 解释操作、拼装上下文、推进状态、校验结果 | static/mobile-service.js |
| 教学规则 | intake 整理需求；roadmap 规划路线；cards 写卡片；tutor 答疑并提取候选记忆 | skills/*.md，打包到 static/skills |
| 模型通道 | 加密密钥、HTTPS 请求、返回结果 | PersonalPlugin.java |
| 持久化 | 保存树、卡片、对话、偏好、记忆和位置 | IndexedDB；密钥独立加密保存 |

安卓版独立运行，不依赖电脑或自建服务器；需要生成时手机直连模型服务。电脑预览沿用 Python 服务与 SQLite，属于另一运行载体。离线可查看已保存内容，不能生成新路线、卡片和回答。

## 3. 从目标到下一次继续学习

### 3.1 需求整理

用户自由叙述，先保存草稿；点击整理后，调用 intake，传入本次叙述与相关个人记录，返回目标摘要、偏好和最多三个关键补问。未知信息保留未知，不用推测补齐。用户可补充、修改后再整理。

确定规则：创建路线前至少明确“学什么、为什么学、希望达到什么程度”；时间和表达方式可采用明确展示的默认值。用户确认的是学习约定，不是每一条模型推断。

### 3.2 路线创建

用户确认目标与约定后调用 roadmap，先生成章节和主要知识点，不生成整门课。当前规则要求 3—4 章、每章 2—3 个节点；业务层生成节点 ID，保存路线、目标、偏好与内容来源状态。代码校验只覆盖部分结构要求，后续应补齐完整校验。

树表示导航轮廓，允许用户跳读。目前主要按节点数组顺序前进，parent_id 仅记录探索分支来源，并没有完整的先修依赖判断。确定规则：后续将“前置依赖”和“章节顺序”分别记录，依赖不足时提醒或提供补充，允许用户自主继续。

### 3.3 卡片滚动准备

路线保存后单独请求首批卡片；因此卡片生成失败时，路线仍可保留并重试。当前以约十张待学卡片为目标，每次最多处理三个尚未准备的节点，每节点规则要求概念、案例、思考三张卡片。首批通常为九张；“十张”是余量目标，不是精确数量承诺。

打开未准备节点时优先生成该节点；继续学习或主动补充时检查余量，充足则不重复生成。当前余量按未完成节点的整组卡片统计，并非精确扣除已经翻过的每一页。

确定规则：后续按未读页数计算余量；不无限预生成。改约定后，新内容和回答采用新约定，已经读过的正文保留；重写已有内容须由用户触发，并保留版本关联，避免旧问答失去对应正文。

### 3.4 阅读与问答

翻页保存节点内页码，选择节点保存当前位置；读到本节最后一页后点击继续，记为“已浏览”并进入下一节点。当前下一节按节点数组顺序选择，探索支线追加在数组后部，尚无单独的主线优先调度。

提问必须绑定发问时的树、节点和卡片。问“这个例子”时优先解释当前卡片；跨页追问再调用历史。当前传给 tutor 的内容包括：本次问题、目标与偏好、当前节点卡片、当前卡片、最近 12 条节点消息、最多 8 组相关交流、最近 20 条个人记忆。检索采用文字匹配和位置加权，属于有界历史检索，不是完整语义记忆。

确定规则：下一步优先处理用户明确选择，其次处理当前未解决困难，再继续主线；探索由用户选择加入分支。普通提问只产生回答，不自动改树。需要补前置、改路线或增加支线时先给出具体建议，用户选择后执行。

### 3.5 退出与恢复

已提交的树、卡片、问答和阅读位置保存在本机，重开后接续。当前未发送问答草稿仅在页面会话内保存，不保证重启恢复；网络生成不承诺在后台持续完成。安卓支持系统分享 JSON 导出，尚未实现导入恢复，导出不应称为完整备份恢复能力。

## 4. 状态与学习证据

| 当前状态 | 准确含义 | 触发 |
| --- | --- | --- |
| unseen | 待学习 | 新节点或重置 |
| learning | 学习中 | 进入相应学习操作或重新学习 |
| read | 已浏览 | 本节最后一页点击继续 |
| done | 用户主动标记完成 | 完成操作或历史记录保留 |
| skipped | 已跳过，理解情况未知 | 用户跳过 |

当前树的点亮与百分比统计 read、done，表示浏览/完成进度，不是掌握率。翻到最后一页不能自动认定读懂；done 也不是独立测评结果。

确定规则：后续将阅读状态与掌握证据分开保存。掌握证据至少包括任务、用户表现、判定依据、时间与适用目标，不用单个总分替代依据。目标为“了解”时允许浏览后结束；目标为“解释、做题、应用”时提供相应可选检查，未作检查就保留掌握未知。一次错误只触发当前知识的帮助，不形成永久能力标签。现阶段不引入未经验证的自动复习公式。

## 5. 个人记忆的更新与使用

当前：保存目标、阅读概况、用户维护的记录及 tutor 最多两条提取结果；记录含来源、树/节点和更新时间。部分记录用稳定 key 覆盖，尚未形成通用去重、冲突处理、过期机制。安卓偏好主要保存在树内，不能宣称所有偏好都已自动进入全局资料库。

确定规则：

1. 对话原文是经历记录，候选记忆是从中提取的信息，两者分开。只长期保留明确目标、稳定背景、带情境的偏好和需要跟进的问题。
2. 区分用户明确表达、操作事实、助手推测；推测不能覆盖明确表达。一次选择不扩展为全局偏好。
3. 同情境下用户的新纠正优先，旧信息标记被替代；不同学科或目标下的差异同时保留。无法判断的冲突先询问，不静默拼成事实。
4. 每条记忆保留来源引用、适用范围、更新时间和有效状态。删除后停止用于后续生成；删除摘要不自动等于删除原对话，界面需明确删除范围。
5. 调用优先级为本次明确要求、当前树约定、相关且有效的旧记忆；检索无依据时直说不知道，不虚构共同经历。后续用相关性筛选替代简单取最近 20 条。
6. 问题有未解决、已回应、用户确认解决等状态；模型给出回答不等于问题已解决。阶段总结更新证据，不将全部原文反复发送模型。

## 6. 保存、失败与内容依据

当前安卓写操作串行执行：复制已保存状态 → 执行业务与模型调用 → 校验结果 → IndexedDB 事务提交 → 返回成功与新状态。普通操作失败保留原状态；模型配置有单独保存步骤，连接测试失败不表示设置未保存。该实现保证本地提交边界，不保证模型服务端的请求取消或费用回滚。

确定规则：保存成功才展示成功；生成失败保留已保存资料与可重试入口；不把失败结果写成正式内容。后续增加请求 ID、重复操作保护和可恢复任务状态，处理超时后重试、切后台或应用退出的情况。当前尚无这些完整机制，也没有统一取消任务能力。

模型正文是生成内容。当前未接入联网检索、来源核验、教材解析或自动配图；不能以提示词要求“准确”替代核验。后续引入资料时，单独记录出处、具体页段和核验状态，并区分“来自指定材料”与“已经独立核验”。个人数据和材料始终作为上下文，不得覆盖教学规则。

## 7. 典型过程与验收

例：用户说“我只想看懂新闻里的导数，不备考，每次十分钟”。整理并确认约定后，生成简洁路线，准备近期卡片。用户要求换成车速例子，回答围绕当前卡片，偏好只在该情境下记录。继续下一节标记已浏览。若用户想理解积分，先建议加入支线，由用户决定；原导数主线保留。重开后恢复位置，不宣称用户已经掌握导数。

设计验收应逐项满足：

- 能解释任意一次生成因何触发、使用哪些上下文、写入哪些记录。
- 路线生成成功但卡片失败时可重试，既有路线不丢失。
- 浏览、跳过、用户完成、测评证据分别表达，百分比不冒充掌握率。
- 跨页问答指向正确卡片；引用旧经历带来源，找不到时不编造。
- 修改偏好影响后续生成；旧卡片与旧问答的对应关系可追溯。
- 用户纠正和删除的信息不继续作为有效记忆使用。
- 断网或保存失败不伪报成功；重启后恢复已提交位置。
- 生成内容、示例与核验资料始终区分。

本次已完成流程、职责、状态及决策规则的文档设计；未实施上述待补齐机制，也未进行真实模型或真机验收。后续开发优先顺序：掌握证据与阅读分离 → 记忆纠正及检索 → 主线/支线调度 → 来源机制 → 可恢复生成任务。
