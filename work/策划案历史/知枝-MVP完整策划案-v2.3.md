# 知枝私人学习助手：MVP 完整策划案

版本：2.3（策划评审版）｜日期：2026-10-23｜范围：产品与运行逻辑设计。2.3 明确最终目标为手机独立运行，并将手机最小可行性验证提前到电脑最小流程之后，补齐两端职责、验证门槛与迁移范围；本轮不开发、不运行模型试验。

本版将早期项目方案、当前安卓进度、需求分析、内容生成、卡片阅读与加强学习、Pi 选型，以及本轮资料和路线设计讨论合并为统一策划入口。本轮只完善文档，不启动开发，不修改应用、正式 skills、数据库或 APK。

**阅读说明与决策状态**

本文区分三种状态：“已选方向”来自当前讨论或工作区最新专项设计；“本版建议默认”用于补齐可讨论、可验收的业务细节，不表示用户逐项确认；“待验证”需要后续技术或真实学习验证。所有未来行为均为设计，不能据此宣称功能已实现或效果已证明。

若旧文档与本版存在差异，先区分用户明确选择和助手建议：新的明确选择优先；本版仅提出的默认值不自动推翻此前明确要求。旧 Word 项目方案仍对应早期版本，未在本轮同步更新。

**一、产品目标与价值假设**

知枝帮助用户从一句学习需求出发，形成有依据、适合当前起点的学习路线，以短卡片连续阅读、主动问答和个人记忆推进；短时间学习后，下一次仍能接回原来的目标与经历。

首轮验证四个价值假设：用户能说清当前方向；卡片短而连贯；反馈能改善后续教学；再次进入时助手能准确接续。功能数量、点亮比例和阅读时长不能直接证明这些价值，更不能代替学习效果。

产品的四个组成保留：学习树承载路线与经历，卡片承载内容，对话承载疑问与反馈，个人资料库承载有情境、有来源的长期记录。知识树的画风、美术和页面细节暂缓，本版只定义行为与状态含义。

**二、首批用户、主题与范围**

已选方向：个人使用、默认主线讲述与完整例子，用户自主提问；加强学习独立、自愿，不锁住主线。最终产品在安卓手机上独立运行：Agent、教学流程、工具与本地资料不依赖电脑开机或电脑服务，模型通过 API 联网调用；离线可阅读已保存内容。验证顺序为先电脑最小流程，再立即验证手机最小运行边界，通过后完善业务并正式迁移。电脑是前期验证载体，不是最终手机应用的必需服务器。桌面宿主和 Pi 具体层次仍需在这些约束下验证。

首批用户以有明确短期学习需要、愿意参与试用的高中生或大学生为主。这是验证对象建议，不代表市场细分、商业模式或规模化用户需求已经得到验证。

| 范围层次 | 本版安排 |
| --- | --- |
| 首批正式验证 | 高中数学、高等数学各少量主题，不承诺覆盖两门课全部内容 |
| 高中主题建议 | 简单函数的导数与单调性，具体范围以用户课程要求和可用资料确定 |
| 高数主题建议 | 变化率、导数定义与基本求导，是否含严格推导由目标决定 |
| 结构兼容案例 | 历史小主题，用于检查通用规则是否过度数学化；不因此宣布历史已完整支持 |
| 开放输入 | 接受其他主题的自由表达；资料或规则未覆盖时明确说明，允许缩小范围、指定材料或只看草案 |

首批主题可换成材料更齐全的同等小范围主题，无需因此改变整体架构。精通整门学科、跨多年全课程规划等目标，先形成可执行的第一阶段成果。

**三、MVP 功能边界与现有基础**

| 类别 | MVP 要求 |
| --- | --- |
| 需求与约定 | 自由表达、关键补问、未知与提议区分、范围与阶段成果可修改 |
| 路线与来源 | 有课程骨架、节点目标和前置关系，资料支持与缺口可追溯 |
| 内容与阅读 | 完整小节点、多页短卡片、主动答疑、当前位置与上下文接续 |
| 个性化 | 反馈影响相关内容，记忆可查看、纠正和删除；学习后归纳经历与策略 |
| 加强学习 | 用户主动进入，围绕节点目标检查，记录依据，随时退出 |
| 可靠性 | 本地保存、失败不伪报成功、明确重试、重开恢复；持续试用前验证导出导入和升级保护 |
| 质量与观察 | 固定案例、资料核对、真实小任务试用、问题与成本记录 |

后置：总/子 Agent 调度、全学科资料库、自动改写正式 skill、复杂自动复习算法、账号与云同步、社区、多用户协作、自动配图、动画和新的视觉体系。仅保留以后扩展的职责边界，不先实现这些系统。

按现有源码说明，安卓 0.6.1 已具备需求整理、路线、卡片、学习树、问答历史、本地相关记录检索、记忆管理和导出等基础。完整迁移版仍待真机验收；导入恢复、前后台与返回专项适配等尚未完成。当前四份规则是阶段提示词，尚未接入 Pi；联网知识检索、完整来源核验和本版教学闭环不能算作已有能力。

因此，下一版应复用界面和数据保护基础，逐项验证新增业务行为，不因重构运行内核就重写所有功能。

**四、用户全流程与阶段出口**

```text
表达需要 → 提取已知 → 必要补问 → 展示可修改的学习约定
                                      ↓
                  匹配课程骨架 → 路线草案 ↔ 资料计划与检查
                                      ↓
                         当前完整小节点生成、审查、保存
                                      ↓
                           阅读 ← 主动答疑与局部调整
                              ↓              ↓
                      准备下一节点       相关记忆及时更新
                              ↓              ↓
                          结束或中断本次学习
                                      ↓
                         整理新增经历与个人教学策略
                                      ↓
                             再次进入恢复并继续

节点详情 → 用户主动进入加强学习 → 保存结果 → 回到原阅读位置
```

箭头表示事件驱动的业务关系，不表示持续运行的模型思考。等待用户输入时结束当次运行，翻页和保存位置不自动调用模型。

| 阶段 | 可交出的结果 | 结束或暂停条件 |
| --- | --- | --- |
| 需求分析 | 目的、范围、阶段成果、暂定起点、未知项 | 信息足够进入草案；阻塞缺口只补问相关内容 |
| 路线准备 | 有版本的结构、节点目标、前置、来源与缺口 | 能合理安排第一小段；远期节点可保留待细化状态 |
| 节点准备 | 要点依据、页序、正文、审查结果 | 发布门槛通过且保存成功；预算到达仍阻塞则暂停 |
| 阅读答疑 | 阅读位置、与卡片关联的问答和反馈 | 用户继续、切换、主动结束或中断 |
| 加强学习 | 题目版本、作答、判定依据与结果 | 通过、未通过或用户退出；不阻塞主线 |
| 学习结算 | 新增经历、未解决问题、教学线索与个人策略 | 去重并提交；失败保留待处理，下次补做 |

**五、需求分析与学习约定**

开场接受自由表达。先提取已有信息，再判断缺口；每轮最多一个主要问题，选项仅在减轻回答负担时提供，自由补充始终可用。默认简短，不为凑选项数量而提问。

核心信息是为什么学、本次主要范围、希望获得什么阶段成果。基础、经历、教材、截止日期和偏好按实际影响处理；明确考试要求或指定教材可能成为核心约束，表达方式和时长通常可以暂定。

信息状态分别保存为用户明确表达、助手提议、未知、冲突待处理；它们不代表知识掌握程度。问了基础但只回答经历时，只更新经历；“高中生”不自动等于已经掌握高中全部前置知识。

多选且有侧重转成主线、次要兴趣和待确定项，不强迫变成单选。用户不知道基础时可以提供带解释的试读；答题式诊断需用户选择，不把备考目标自动解释成同意每页测验。

学习约定包括目的、学段/课程范围、阶段成果、边界、起点及依据、相关约束、偏好与未知项。展示简短的人话版本，允许自然语言“按这个开始”或修改；未回应不视为接受。用户只想先看路线时交出草案，不能标成已确认正式课程。

约定修改保留版本。目的、范围和成果变化需要更新对应约定；只换例子或表达顺序，不要求重做整轮访谈。

**六、资料从哪里来、怎样使用**

资料不靠预先人工编写所有知识点，而按任务获取。先确定学段、课程或版本、目标深度，再检索当前节点所需内容。MVP 采用少量受维护的资源目录、按需读取和本地缓存；不以先建全学科大型知识库为前提。

| 来源 | 获取与使用规则 |
| --- | --- |
| 用户指定材料 | 先支持链接、粘贴文字和可识别文本资料；扫描 PDF、复杂公式与课件批量解析后置。指定不等于内容必然正确，冲突仍需检查 |
| 课程资源目录 | 记录课程/教材名称、版本、学段、主题、语言、可读入口和适用范围，由维护者初步筛选，不直接把搜索排名当质量 |
| 联网补充 | 针对明确缺口查询，实际读取原文后登记；拿到搜索摘要不等于已核验全文 |
| 既有缓存 | 复用有来源的片段和节点关联；教材或目标变化时重新检查适配性，个人资料不自动进入公共资源目录 |

首批资源选择是后续材料验收任务：每个正式验证主题至少有一套匹配范围的课程或教材依据，以及能检查关键结论的材料。当前文档不虚构已取得教材、许可、搜索接口或网页读取能力。读取和缓存须符合来源的使用条件。

资料条目至少保留标题、作者/机构、版本或日期、网址或文件标识、章节/页码/段落、实际读取时间、原文关联、支持的要点及限制。数学片段保留公式、变量、条件及必要上下文，不按固定字数截断证明或例子；识别有疑问的公式不得直接当作可靠依据。

每个知识要点分别标记：已读取材料支持、完成有记录的比对/验证、模型生成尚无材料支持、未解决。前两者也要说明范围；一个来源有效不代表整节点全部结论已核验，模型自报的引用不能冒充工具实际读取记录。

有限检索按缺口结束：核心要点有据、必要条件明确、例子自洽、关键冲突已处理，就可以准备当前节点。非必要拓展可推迟；争议可以保留并说明；核心结论缺依据则暂缓相关部分，缩小范围需说明，改变约定范围需用户选择。没有联网工具时可用已有材料，不能假称搜索完成。

**七、路线怎样同时追求正确与高效**

路线正确主要检查目标匹配、知识覆盖、依赖与来源；效率通过合理取舍和真实使用观察。不能承诺唯一最优路线，模型自检、节点少或生成快都不构成学习高效的证据。

采用：明确成果 → 匹配课程骨架 → 判断起点 → 裁剪与补前置 → 生成路线 → 程序结构检查与资料审查 → 根据表现局部调整。

每个节点至少说明：学习价值、可观察目标、必学或选学、前置节点、依赖是必要还是建议、采用的课程依据、待核实点，以及可供自愿加强使用的检查方式。目录是骨架，关键依赖要读取材料验证；不同教材的教学顺序不自动等同于必要依赖。

程序检查节点引用、重复、循环依赖与版本；模型配合资料检查目标是否遗漏、学段和深度是否匹配、前置是否充分、是否包含无关拓展。前置是模型推断时需保留推断性质，结构合法不等于教学合理。

整体路线先展示轮廓，当前和近期节点详细核对，远期节点标明暂定。若整体范围和关键前置尚不清楚，只能展示路线草案；第一小段具备依据可以开始，不把所有远期内容都说成已验证。证据充分的旧知识可以简短回顾或跳过；未知基础采取可调整起点，主线不强制测验。

节点不服务目标且不是必要前置时，移到选学候选或说明价值。发现知识缺口先补局部解释；只有确实影响结构时才增加节点或重排。路线版本关联生成内容，旧路线和学习经历可追溯。

**八、节点生成、卡片编排与发布门槛**

先确定完整小节点的目标、价值、前置和边界，再整理要点、编排页序、写正文、检查和保存。这些是逻辑步骤，可以合并调用，不要求每一步都新建 Agent 或发起独立请求。

概念型节点通常包含定义与白话诠释、典型例子、必要区分与边界、用途和衔接；环节可以合并或拆页。程序型节点按步骤和原理组织，历史专题按背景、证据、事件与解释组织。每页一个小目标，不固定三张，不为短而删必要条件。

节点主标题稳定，页内副标题随卡片变化。主线示例直接给完整解释和计算，不默认附题，不每页问“懂了吗”。原创例子标明简化或虚构，假设完整，与概念相符。

发布前留下“必要要点—依据—卡片位置—未确定项”对照，检查有用、有据、准确、前置充分、例子有效、深度合适、页间连贯，并确认没有误插强制作答。

| 发布条件 | 不满足时的行为 |
| --- | --- |
| 节点目标和必要内容清楚 | 回到节点任务，不用正文掩盖模糊目标 |
| 核心结论、必要条件有可读取的依据 | 补资料或缩小草稿；阻塞部分不作为正式内容发布 |
| 定义、例子和必要边界一致，无关键断层 | 定位并有限修订；不能以文案通顺替代正确性 |
| ID、引用、页序、版本与约定一致 | 拒绝提交，保留草稿和具体问题 |
| 无未处理的阻塞问题，保存成功 | 才标记可读正式版本；失败不伪报发布成功 |

改善措辞或局部冗余可作为后续优化；事实错误、关键条件缺失、核心依据不足和必要前置断层属于阻塞。一次自动修订后仍有阻塞，保留草稿并停止该任务，不无限生成相似答案。该次数是暂行策略，不是已验证最优值。

首批完成一个完整小节点后开始阅读，随后准备下一节点；更远处只保留轮廓。当前提问与主动打开的内容优先于后续备课，不让长请求阻塞翻页和本地保存。后台持续生成未获保证，离开应用后允许中断，下次继续或重试。

示例要点表（结构示意，须在实际材料读取后填写）：

| 导数直观入门节点的必要内容 | 依据记录 | 卡片职责 | 检查关注 |
| --- | --- | --- | --- |
| 平均变化率到瞬时变化率的联系 | 课程章节/实际片段引用 | 建立问题和直观 | 必要符号及情境是否解释 |
| 当前目标需要的导数含义 | 对应定义及适用条件 | 定义与白话诠释 | 直观解释是否被误写成严格证明 |
| 一个完整简单例子 | 例子来源或原创标记 | 展示过程及概念对应 | 数值、变量与结论是否一致 |
| 必要边界和后续关系 | 支持材料和页段 | 区分误解并衔接 | 是否暗示所有位置都可导，或无关扩展 |

该表示意不构成已完成数学核验的课程或卡片。

**九、主动答疑、反馈与路线调整权限**

问答绑定发问时的树、节点、卡片及正文版本。用户翻页或切树后旧回复返回，仍归属原位置，不写到新页面。问“这个例子”优先解释发问时的卡片，跨页再查相关历史；找不到记录就说明，不虚构共同经历。

反馈先作用于当前问题，再影响相关的未读或未生成内容。已读正文不因普通偏好变化批量覆盖；明确知识错误应停止作为有效依据，保留更正记录并提示受影响内容，旧版仅供追溯。

采用较宽的教学调整权限，同时把目标边界交给用户。下列划分为本版建议默认，用具体案例约束，不要求每个小动作审批。

| 情况 | 权限与处理 |
| --- | --- |
| 当前例子陌生、术语没解释、要求分步讲 | 直接局部处理，保留原目标 |
| 当前节点补一句回顾或一张必要基础卡 | 直接处理，不自动贴能力标签 |
| 在原范围内增加必要前置节点 | 可执行并简短告知原因，保留版本和撤回入口；若明显增加负担则先建议 |
| 重排未读的相关节点、推迟选学拓展 | 可执行并告知，已读经历和问答不丢失 |
| 用户说太简单 | 可缩短重复和建议跳过，不直接写成已掌握 |
| 用户问一个延伸问题 | 先答；需要新目标或较长支线时让用户选择是否加入 |
| 了解型改为系统备考、转另一主题、显著扩大范围或时间负担 | 先展示新约定或建议，用户明确选择后执行；沉默不算认可 |
| 用户否决调整或要求恢复 | 撤销对应安排，标记后续相关草稿过时，保留历史 |
| 来源冲突或内容被质疑 | 核验相关结论；不把知识错误解释成用户能力不足 |
| 只有翻页或长时间未提问 | 仅保存阅读事实，理解与满意程度仍未知 |

“重大变化”不按节点数量机械判定，而看是否改变目的、阶段成果、范围、关键前置要求或原约束。撤回恢复的是安排和有效版本，不抹掉已经发生的学习记录。

**十、学习树、阅读与独立加强学习**

阅读与学习证据分别保存。首次到节点末页点击继续，表示完成该节点浏览，树可绿色点亮；进度表示浏览进度，不能称掌握率。跳过保存为跳过，返回重读不丢原位置记录。

加强学习从节点详情主动进入，不在读完时弹出，不默认开启，不提供常驻自评掌握，不作为继续阅读的条件。进入前保存主线位置；退出后回到原位置。加强结果以橙色及文字/符号呈现，具体视觉后置。

本版建议的通过流程：

1. 按节点目标列出需要观察的核心表现和对应题目依据。了解型检查含义与限制，计算/应用型检查实际操作，不扩展成整门课测验。
2. 选择题先有可核对的答案与解释，开放回答先有判定要点及常见等价表达，再收集作答；生成错误或有歧义的题目不能用于判用户错误。
3. 判定为通过、证据不足或存在具体错误。记录覆盖了哪些目标；语义含糊先指出缺口，不按措辞硬匹配。
4. 核心表现均有对应有效证据、无未处理的关键错误时，保存为当前目标版本的一次通过；未覆盖完整目标只能保留部分证据，不点整节点通过标记。
5. 未通过时给解释，可用等价新例子重试、回看或退出，不扣阅读进度，不自动强制补课。

具体题量随目标和作答调整，不预设各学科同题数、同分数线。题目和判定方式必须先在首批案例中校准；MVP 不宣称通过一次检查等于永久掌握。

通过记录绑定节点目标、内容和题目版本。目标实质变化时旧证据注明适用旧版，不自动充当新版通过；旧记录保留。之后一次未通过不删除此前有效证据。未浏览但主动加强并通过时，可以显示通过记录，浏览进度仍单独统计。

未进入加强学习不影响正常使用，也不表示缺乏积极性。产品试用可以邀请用户自愿完成迁移或回顾任务，评价过程不能偷偷变成主线强制测验。

**十一、个人记忆、学习结算与连续性**

记忆独立于 Agent 对话窗口保存，分为原始记录、个人资料、学习证据、讲解连续性和个人策略。以下是业务职责分类，不要求第一版建设五套数据库。

| 类型 | 内容 | 边界 |
| --- | --- | --- |
| 原始记录 | 原话、卡片关联、操作、作答、来源和时间 | 原始事实优先保存，可回溯摘要 |
| 个人资料 | 明确目标、背景、带情境偏好和纠正 | 不把一次选择推广为永久偏好 |
| 学习证据 | 具体任务、表现、判定依据、适用目标版本 | 讲过、看过、通过检查分别记录 |
| 讲解连续性 | 已介绍的概念、例子及条件、尝试过的解释、疑问 | 帮助下次承接，不等同于用户理解 |
| 个人策略 | 针对相关情境，下次应该怎样讲 | 有来源、有适用范围；效果未知就标未知 |

例如“这个速度例子没懂”先对应当前困难；确认是术语跳步后可以形成“本节点先解释平均变化率”的策略，不能直接写成“数学基础差”。同样，喜欢历史时间线不自动意味着数学也只用时间线。

反馈及时生效，学习结束再归纳，不能让用户等结算才获得调整。本版建议一次学习活动从开始某个目标，到明确结束或切换另一目标；切后台仅暂停，异常退出保留未结算状态。重开可继续原活动或按实际操作开始新活动，不因时间间隔推断用户学过未记录内容。

结算只处理上次已处理位置之后的新增事件：归纳学了什么、讲过哪些可复用概念和例子、有哪些未解决问题、用户明确反馈是什么、哪些策略值得沿用。没有新增内容则不重复调用；无需用户填写额外总结。

输入记录活动 ID 和事件范围，输出保留来源引用和合并建议。程序用活动、事件区间和规则版本识别重复处理，提交成功才推进处理位置；失败下次补做，原始记录和阅读位置先保留。中断发生时不依赖应用关闭瞬间完成网络请求。

记忆冲突按以下规则处理：本次明确纠正优先于旧偏好；同情境新信息可替代旧信息并保留关系；不同情境可以并存；助手推测不覆盖用户明确表达；无法判断且影响下一步时只问相关缺口。问题被回答不等于解决，用户明确反馈或后续有效表现才支持更新解决状态。

用户可查看、纠正、删除相关记忆。删除摘要与删除原始对话分别表达；请求忘记某项时，相关衍生记忆同步失效，保留原始记录的情况下也不能从它自动重建同一条已要求忘记的记忆。检索与缓存一并停止使用失效记录。完整删除与审计细节以后续数据设计落实。

生成前按当前目标、节点和问题查相关经历；全量历史不反复发送。跨树引用须能指向实际旧记录，并说明适用关系；不能因为学过高数，就假定所有高数前置已经掌握。

**十二、主 prompt、skills、学科规则与工具**

MVP 采用一个学习主 Agent。主 prompt 保存稳定职责与通用边界；流程 skills 保存具体任务方法；学科参考规则补专业要求；每次任务数据提供约定、节点、相关材料和记忆；工具说明与运行时校验约束实际操作。

| 组成 | 最小职责 | 本版边界 |
| --- | --- | --- |
| 常驻主 prompt | 围绕目标、保留未知、使用依据、不冒充掌握、依据工具结果判断保存成功 | 简短稳定，不塞整门课内容和全量历史 |
| 需求 skill | 提取、补问、约定与交接 | 不默认测基础，不反复问已明确信息 |
| 路线 skill | 匹配课程、依赖与取舍、路线审查 | 不把模型熟悉的目录当作唯一标准 |
| 内容 skill | 要点、页序、正文与七项检查 | 逻辑步骤可合并，不固定每节点三张 |
| 答疑 skill | 正确定位卡片、处理反馈与局部调整 | 普通问答不随意改变目标 |
| 加强 skill | 按目标生成检查、判定依据与解释 | 独立模式，可退出 |
| 记忆结算 skill | 整理新增经历、连续性和个人策略 | 只提候选，程序校验与提交 |
| 学科参考与方法 | 数学条件与推导、历史证据与解释，例子、比较、分步示范等 | 按需组合，不为每门学科复制整套流程 |
| 工具及程序 | 检索、读取、版本、ID、权限、结构检查、去重、落库 | 来源与用户数据是上下文，不得覆盖系统规则 |

每份 skill 的设计说明统一包含触发、输入、方法、输出、质量标准、异常出口和版本；补少量有效与失败示例。当前正式四份规则不在本轮修改，后续迁移需同步提示词、校验和业务逻辑，不能只改 Markdown 标题。

本版不假定 Core 自带完整 SDK 的 skills 加载和会话持久化。选择 Core 后由知枝显式提供当前规则和必要上下文，关键阶段不单靠模型自主发现 skill。

**十三、最小数据契约与状态区分**

本阶段只定概念、关联和校验要求，不编写 TS 接口、数据库迁移或正式工具代码。字段名、存储结构属于后续实现，下面是共同业务契约。

| 对象 | 至少记录 | 与其他对象的关系 |
| --- | --- | --- |
| 学习约定 | 目的、范围、成果、信息状态、来源、版本和接受情况 | 路线引用明确版本，未回应不接受 |
| 路线与节点 | 稳定 ID、目标、价值、依赖性质、必选/选学、依据与缺口、版本 | 卡片、事件、加强结果引用节点版本 |
| 资料与要点 | 实际读取记录、位置、支持结论、状态和限制 | 引用可定位，模型不能凭空造有效资料 ID |
| 卡片计划与正文 | 页序、小目标、节点引用、资料引用、审查与正文版本 | 已读记录及问答指向当时版本 |
| 学习事件 | 用户原话/操作/作答、时间、活动与对象引用 | 为反馈、记忆、证据和结算提供原始依据 |
| 记忆与策略 | 内容、性质、情境、来源、更新时间、有效/替代/删除状态 | 检索仅使用相关有效项 |
| 加强记录 | 目标及题目版本、作答、判定依据、覆盖项、结果与时间 | 不直接替换浏览状态 |
| 运行任务 | 请求 ID、目标版本、预算、阶段、结果、失败/中断原因 | 校验后一次提交，重试可识别重复 |

必须分别记录的信息状态、来源状态、阅读状态、内容发布状态和加强证据不能混成一个“完成度”或“可信度”总分。建议内容状态为草稿、缺资料、待修订、可发布；任务状态为等待、运行、成功、失败、中断、版本过时。名称可调整，含义保持一致。

程序分配 ID 和版本，模型给业务建议。TS 帮助开发时约束类型，运行时仍要检查模型输出的字段、引用、作用范围和版本；两者都不代替知识正确性核查。正式数据更新在同一明确提交边界完成，避免工具写一次、结束回调再写一次。

**十四、技术路线与执行边界**

主语言方向为 TypeScript，优先复用已有界面与业务基础。最终安卓载体沿用 Capacitor 和现有 Java 原生能力；电脑验证阶段可采用本地 Node/Bun 进程配本机网页入口，不以制作完整桌面客户端为前置工作。Python 沿用资料处理和构建辅助，Skills 与参考规则以 Markdown 管理。实际依赖版本、桌面系统和安装包细节仍在后续技术阶段验证。

运行位置分别确定用户入口、Agent/工具执行地点、资料保存地点和模型推理地点。最终手机上的界面、Agent 执行、教学状态、记忆与资料库均在手机；远端模型经 API 提供推理，搜索与资料网站是可选外部信息服务。前期电脑用对应本地实现验证同一业务契约。电脑服务和自建云端 Agent 都不是最终手机使用的必需依赖，手机也不需要通过局域网访问电脑才能学习。

| 方案与状态 | 用户与执行位置 | 主要价值与代价 | 对 Pi 的影响 |
| --- | --- | --- | --- |
| 安卓手机本地（最终目标，已选） | 手机上阅读、运行 Agent/工具并保存资料 | 电脑不开机也能使用；需解决 WebView、系统中断和原生通道适配 | Core 为优先验证候选，必须经过实际手机验证 |
| 电脑本地（前期验证阶段，已选） | 电脑上运行验证入口、Agent 与本地资料库 | 先检查最小业务；不以完善桌面包装或全部功能为先 | 运行逻辑须隔离桌面依赖，桌面通过不代表手机兼容 |
| 手机访问电脑服务（未采用） | 手机只是客户端，Agent 仍在电脑 | 依赖电脑开机与网络，不符合最终手机独立要求 | 不用这种办法冒充手机 Agent 已独立运行 |
| 云端 Agent（对照，未采用） | 手机访问自建远端 Agent | 会改变既定执行与数据保存位置，当前不进入实施范围 | 模型 API 位于远端不等于采用云端 Agent 部署 |

电脑本地不要求运行手机应用，也不意味着只能使用命令行；界面可通过本机网页呈现。手机访问电脑上的服务仍依赖该电脑运行与网络连接，不能称手机独立运行。纯浏览器运行 Pi 与在电脑 Node/Bun 中运行 Pi 是不同环境。

本地保存与执行不等于数据永不离开设备：调用模型时仍需发送完成任务所需的上下文，联网检索需发送查询。模型 API 联网可用时生成新内容；离线可阅读已保存卡片、查看本地树与记录，暂不承诺离线生成。把模型下载到手机、设备端训练或部署本地大模型均不列为本版要求。

Pi Agent Core 仍为手机独立运行目标下的优先验证候选。桌面完整 SDK 可以作为减少上层工作的对照方案，但不能因桌面方便就把 Node/Bun 专属能力写进共用教学业务。最终运行层选择必须满足手机最小可行性门槛；使用相同语言、模型或规则都不自动证明运行兼容。知枝负责的目标、资料、记忆和提交契约不依赖某个 Pi 会话文件格式。

Pi 官方的 [Core 文档](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md)与 [SDK 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md)描述的是通用运行能力，不保证本策划的教学流程或移动端适配。

现有安卓插件主要传 system/user 文本并返回正文，尚不能直接视为完整工具协议适配。后续技术验证需在实际 WebView 中确认依赖、完整消息与工具调用/结果传递、错误与取消、密钥留在原生层，以及重开恢复已提交状态。桌面 Node 示例通过不能代替安卓验证。

若移动端 Core 不适配，停止扩大依赖该内核的桌面实现，定位是依赖、消息协议、网络还是生命周期问题，再评估适配或替换运行层；可用既有阶段式请求保留部分业务验证，但不能把缺少工具循环说成 Pi 已接入。不默认改成手机调用电脑服务。改变手机独立运行目标需要重新作出产品决定，不能用技术绕行静默替换。未来子 Agent 如确有必要，也复用相同运行内核与受控业务工具；当前不开发委派系统。

两端职责与迁移范围明确如下：

| 尽量共用的业务 | 需要平台适配的能力 |
| --- | --- |
| 学习约定、路线及节点规则、卡片生成与审查、反馈动作、记忆语义与检索契约、结算逻辑、skills 和案例 | 存储、文件与资料读取、密钥、模型网络、系统分享、任务取消与应用生命周期 |
| ID、版本关系和业务数据格式 | 电脑本地存储与手机 IndexedDB/原生存储的读写实现 |

共用 TS 业务只依赖清楚的能力接口，不能直接调用桌面文件系统或进程功能。迁移时保留目标、节点、卡片、证据与来源关联；需要转移电脑试用档案时校验格式与版本，不能只复制桌面数据库后宣称手机可读。密钥由各设备安全保存与重新配置，不混入普通学习档案。迁移目标是同样的业务行为，不承诺两端共享运行进程、数据库实现或同一个安装包。

本策划中的用户本地指用户自己的电脑或手机。当前 Tutti 托管工作区属于开发与文档环境，在这里启动程序不能证明应用已部署到用户设备。本轮不启动任何服务。

**十五、失败恢复、等待与调用成本**

| 情况 | 产品行为与保存要求 |
| --- | --- |
| 模型超时、断网、限流 | 保留原话及已提交内容，显示本次失败与重试；不在后台无限重发 |
| 资料不可读或检索不可用 | 展示资料缺口，允许指定材料、换来源或缩小草稿；不标记核验完成 |
| 返回结构错误 | 有限修复，仍失败则保留草稿；不写入无效正式对象 |
| 保存失败 | 不显示发布或记忆更新成功，保留可重试内容与错误原因 |
| 连点或重试 | 同一次逻辑任务去重，避免重复卡片、事件与记忆；用户新需求使用新任务 |
| 用户改变目标，旧请求返回 | 对比约定、节点和相关策略版本，旧结果标记过时，不覆盖新安排 |
| 切后台、退出或系统回收 | 已提交资料可恢复，未完成任务明确中断；不承诺后台请求继续执行 |
| 当前问答与备课竞争 | 用户当前操作优先，备课可暂停；翻页和本地位置保存不等网络 |
| 导出、导入与升级 | 导出不含密钥；导入校验格式和版本并说明覆盖/合并影响；失败不破坏当前资料，固定签名和真实覆盖升级需验收 |

后续应提供可理解的运行状态：正在查资料、准备内容、检查内容、失败待重试。具体 UI 后置，不用虚假的进度百分比或固定完成秒数掩盖等待。

本版建议暂行预算如下，仅供小范围验证；不是既有 Pi 参数，也不是性能承诺：

| 任务 | 一次逻辑任务的建议上限 | 到达上限后的行为 |
| --- | --- | --- |
| 需求一轮/普通答疑 | 模型请求最多 4 次、工具调用最多 3 次；格式修复最多 1 次并计入总数 | 保留已知内容与原因，给出简短结果或重试入口 |
| 一个完整小节点 | 模型请求最多 8 次、工具调用最多 6 次、自动内容修订最多 1 轮，全部计入总预算 | 保留草稿和阻塞项，停止生成，不以到达预算作为通过 |
| 一次新增记录结算 | 模型请求最多 2 次，含一次必要修复；无新增事件不调用 | 标记待处理，下次前台运行补做 |

这些是上限，不要求用满。检索围绕节点缺口按批次进行，外部搜索次数还需结合所选服务设置，不能把一轮模型调用等同于一次搜索。加强学习按用户一轮作答设置相同有限运行原则，整段自愿活动可以有多轮，不隐藏自动循环。

记录请求数、工具次数、可获得的 token/费用信息、等待时间、修订次数和未解决问题；服务没有提供准确费用时不能展示成实际账单。先控制无用调用，再依据记录调参数，不以缩短解释或删除必要条件换低成本。

**十六、质量验收与试用设计**

策划验收与产品验收分开：本文应让每个阶段的输入、输出、依据、调整权限和失败出口明确；产品仍需实际实现和试用。下列均为待执行案例，不是通过记录。

| 编号 | 场景 | 预期观察 |
| --- | --- | --- |
| A01 | 一段话已说明目的、范围与基础 | 提取已有信息，不重复问；未覆盖项仍未知 |
| A02 | 只回答经历，漏答理论基础 | 不把经历换算为程度，不强迫自评 |
| A03 | 多个目标都有兴趣但有侧重 | 主次保留，阶段路线体现优先级 |
| A04 | 没有回答约定，或只要求先看路线 | 不自动接受；展示可改草案或明确试读 |
| A05 | 同一“导数”主题分别面向高中、高数或直观了解 | 范围、深度和材料匹配目标，有前置依据 |
| A06 | 路线缺必要前置、存在环或无关节点 | 能定位问题并修订，程序和资料审查各自发挥作用 |
| A07 | 核心来源缺失、公式识别不清或资料冲突 | 不伪造引用，阻塞内容不发布，给出可继续的处理路径 |
| A08 | 一个新概念完整节点 | 定义、诠释、例子、必要边界和衔接连贯；不固定三张卡 |
| A09 | 用户只想阅读，不回答知识问题 | 主线持续可读，不弹测验，不认定已掌握或不积极 |
| A10 | 用户说当前例子不懂 | 正确定位卡片，局部调整，并影响相关后续内容 |
| A11 | AI 补前置或用户改变目标 | 局部调整按权限处理；重大变化取得选择，保留版本和撤回 |
| A12 | 主动加强、通过、退出或未通过 | 判定有依据，阅读位置不丢；未通过不扣进度，不强制补课 |
| A13 | 加强题歧义、目标改版或已有通过后再次出错 | 题目问题不算用户错误；新旧目标与证据不混淆，历史记录保留 |
| A14 | 用户纠正或要求忘记偏好 | 后续相关生成停止使用旧信息，不从摘要或缓存重新灌回 |
| A15 | 结算重复执行、失败后重开 | 原始记录仍在，按新增范围补做，不生成重复记忆或伪造解决状态 |
| A16 | 跨树引用，或旧偏好不适用于新学科 | 有来源且确实相关，必要时不引用，不牵强套用 |
| A17 | 断网、保存失败、重复请求或乱序返回 | 不丢已提交资料、不伪报成功、不让旧结果覆盖新版本 |
| A18 | 真机切后台、返回、重开、导入导出和覆盖升级 | 状态含义清楚，资料可恢复，密钥不混入普通档案 |
| A19 | 生成后修改通用规则 | 记录规则版本；旧内容和问答可追溯，不批量静默重写 |

内容审阅先按指定资料核查首批主题的覆盖、依赖、定义与条件；可由熟悉课程的人参与，不把同一模型重复自查当作独立权威。再邀请少量目标用户完成自愿的小任务试用，保留原始反馈。

观察分三组：可靠性看恢复、写入与错误；教学质量看来源、遗漏、跳步与目标匹配；学习价值看用户能否说清位置、反馈是否被正确采用，以及自愿检查中能否解释或应用到新情境。等待、重写和重复提问是诊断线索，不直接等同满意或学习收益。

进入持续试用的建议门槛：上述适用的关键行为案例逐项通过；无未处理的资料丢失、核心知识错误或虚假来源等阻塞问题；首批每个主题至少走完一次有记录的完整学习过程和一次中断恢复。尚未执行的项目明确留空，不以文档齐全代替验证。

不预设“提升多少分”“效率提高多少百分比”或统一通过率。缺少对照和样本时只报告观察结果，不能作效果宣传。

**16.1 已选部署顺序下，怎样分阶段验证**

采用“纸面走查 → 电脑最小运行 → 手机最小可行性验证 → 完善业务并做故障与真实学习验证 → 正式迁手机与移动专项”。手机最小验证在电脑小流程之后、全面扩展和桌面完整包装之前进行。本轮只完成验证设计与可检查的预期行为；后面的程序、模型、故障模拟和设备操作均在未来进入执行阶段后进行，不由本次讨论自动启动。

第一步：纸面走完整过程，先找规则冲突。

准备两份边界明确的学习情境、一小份实际可读取材料，以及预期行为表。高中案例可用“已有求导接触，想判断简单函数的单调性”，高数案例可用“想理解导数定义，基础暂不清楚”。具体数学内容需在选定材料后核对，场景本身不证明路线正确。

逐步列出用户输入、已有证据、当前状态、Agent 应做的动作、应保存的内容、应显示的结果。至少走过：漏答基础、确认范围、路线草案、首节点、主动说没懂、修改讲解、结束结算、再次继续，以及一次主动加强。此步验证产品逻辑和契约，不测试模型效果或 API 稳定性。若预期动作本身说不清，先改策划，不用增加 prompt 掩盖矛盾。

第二步：后续只在电脑搭最小运行载体，验证真实 Agent 循环。

不以重做界面为起点，可复用现有界面或使用足够展示结果的本地入口。模型、Pi、skills、工具和业务数据先跑通同一个小主题。首轮使用固定材料，减少自动检索的变量；真实工具至少完成一次读取学习状态、取得相关材料、返回结果供 Agent 继续工作的循环。正式数据仍由受控提交完成，不能靠模型说“已保存”判断成功。

记录约定与节点版本、资料实际读取位置、所用规则与模型版本、关键工具结果和最终业务结果，不要求保存模型隐藏推理。一个节点生成、审查、发布、主动答疑、反馈影响下一次相关生成、结算和恢复必须真正衔接。仅能聊天或输出 JSON，不算此步通过。

本阶段只做足够验证契约的一个小主题，不扩展全课程、全部资料接口或完整桌面外壳。通过后立即进入第三步。自动检索扩展、更多学科和完整异常覆盖安排在手机可行性确认后的业务完善阶段。

第三步：立即在目标安卓手机做最小可行性验证。

使用同一份小主题输入、业务契约与固定材料，在手机完成 Agent 运行、一次真实工具调用与结果回传、模型 API 请求、本地保存和重开恢复。测试手机应能独立访问模型服务，关闭验证电脑或断开与电脑的服务连接后，仍可完成这条流程。不能只在手机浏览器打开电脑页面作为通过证据。

| 手机早期门槛 | 可接受的通过证据 |
| --- | --- |
| 运行与工具 | 在实际 Android 环境执行选定 Pi 路径，模型能调用工具并收到有效结果，不只有文字回复 |
| 网络与密钥 | 手机直接请求模型，密钥留在原生安全存储，不靠桌面代理传递凭据或请求 |
| 保存与恢复 | 卡片、目标、学习位置保存后退出重开仍在，版本与来源关联不丢失 |
| 中断处理 | 切后台或中断后，任务完成、失败或中断状态可解释，未保存不报成功；不要求后台持续运行 |
| 独立性与离线边界 | 电脑未运行时仍能联网生成；手机断网后可读已保存内容，新生成明确不可用或待重试 |

门槛未通过时，先修平台适配或重新评估内核，不开展依赖未验证能力的大规模桌面扩展。通过只证明这条最小路径在该设备可行，不代表完整手机产品、所有设备或教学效果已通过。

第四步：完善业务，把故障和用户变化当作正式案例，再做小范围真实学习。

此时再逐步以自动检索替换固定材料，并重跑相同节点，分辨资料获取问题与教学编排问题。资料不足时确实停止或保留缺口，不能自动补成确定结论。更多主题、记忆情境和完整状态处理按同一契约增加。

| 必走情况 | 要检查的结果 |
| --- | --- |
| 生成中断、重开本地应用 | 已提交内容、位置和目标仍在，未完成任务可解释，不伪报完成 |
| 模型格式错误或写入失败 | 错误结果不成为正式卡片，原资料不被覆盖 |
| 同一任务重试或旧请求晚到 | 不重复创建，不覆盖新目标或策略版本 |
| 用户修改或要求忘记偏好 | 相关旧信息停止使用，结算与缓存不再自动恢复它 |
| 资料缺失、冲突或核心计算有误 | 能阻塞错误内容、定位要点和修订，不以“模型已检查”放行 |
| 只阅读、不做加强 | 主线可继续，浏览与掌握证据分开 |
| 当前反馈影响后续内容 | 能指出改变了哪一段、为什么改、使用了哪条实际记录 |

通过可复现案例后，再邀请少量自愿用户完成实际小目标；验证者与使用者不必全部是同一人。由熟悉课程的人按指定材料核对路线覆盖、依赖和内容错误；学习者反馈目标是否清楚、内容能否接上、哪里仍有困难。产品内主线保持不强制测验，试用中的学习检查另行征得自愿参与。

比较改动前后的同等任务或等价新例子，观察关键错误、遗漏前置、重复解释、实际完成表现和耗时；保留不同基础的差异。单次做对或满意反馈只是线索，不能宣称已经证明学习效率提升。样本很小时报告具体案例，不包装成统计结论。

第五步：依据已经通过的手机最小路径，正式迁移并做完整真机专项。

手机最小路径已经在第三步验证，此步处理完整业务和真实使用差异。先用少量版本化的学习档案验证转移或恢复，再检查卡片、问答、记忆和加强证据在手机上的引用。迁移发现的平台问题不得反过来悄悄删掉核心业务要求，应明确定位并修订对应方案。

尽量共享 TS 教学业务、资料和记忆契约、规则及相同验收案例；文件读取、数据库、密钥、模型网络、系统分享和生命周期通过平台适配处理。桌面 Node/Bun 能力不能直接进入手机业务层，完整 SDK 若只适合桌面应限定在桌面运行适配中。共享业务逻辑不等于共享同一个运行进程、SDK 部署或安装包。

重放相同业务场景时比较结构、目标覆盖、来源和状态行为，不要求两端模型生成文本逐字相同。随后补手机键盘、返回、切后台、断网、导入导出和覆盖升级的真机专项。桌面通过记录与手机通过记录分开保存。

| 验证层次 | 证明了什么 | 不应据此宣称什么 |
| --- | --- | --- |
| 纸面走查 | 规则与预期行为可解释 | 模型或程序已经可用 |
| 手机早期最小路径 | 指定设备能独立运行约定的 Agent、工具、模型请求与保存恢复 | 完整功能、全部手机兼容或后台持续运行已通过 |
| 桌面运行与故障案例 | 本机 Agent、工具、持久化及业务衔接可运行 | 手机可用、知识全部正确或效果已证明 |
| 资料核对与真实小任务 | 首批范围内观察到的教学问题和使用表现 | 全学科覆盖、对所有用户有效或统计提升 |
| 手机切片与真机案例 | 目标设备上的运行和移动使用边界 | 任意设备兼容或永久无故障 |

每一步保留输入、依据、输出、问题、修订与复核结果。遇到核心知识错误、资料丢失、虚假来源或反馈未生效时，回到对应环节修正后重跑相关案例，不以继续增加功能替代修复。

**十七、规则维护与后续阶段**

三个循环分别管理：当前内容修订、个人适配、通用规则升级。前两者由具体学习事件驱动；第三者先登记可复现问题，个人结算不自动改写正式 skill。

通用规则问题记录输入、所用版本、原输出、预期行为、问题归属与候选修改。材料错误先修材料，个体偏好先修个人适配；确认通用漏洞后，用固定案例比较影响和调用代价，再决定是否发版。自动采用范围与发布权仍留待单独讨论，当前默认不自动发布。

后续阶段只列规划，不在本轮执行：

| 阶段 | 主要交付 | 进入下一阶段的依据 |
| --- | --- | --- |
| 现在：策划评审 | 本文、关联专项规则、纸面场景与未决项 | 关键行为无冲突，新增建议被清楚标记；不启动开发 |
| 材料与样例验证 | 首批真实材料、一个节点的要点/页序/正文/检查样例、一次结算样例 | 能核对核心结论与反馈映射；仍可先在文档中模拟 |
| 电脑最小运行验证 | 一个小主题、固定材料、单主 Agent、工具与本地保存的最小衔接 | 能观察到实际工具结果、业务状态和恢复，不扩展全部桌面功能 |
| 手机早期可行性门槛 | 同一小流程在目标手机独立运行，验证模型/工具、密钥、保存与中断 | 电脑不开机仍可用；失败先处理适配，不进入大规模扩展 |
| 业务完善与电脑小范围试用 | 反馈、结算、加强、检索、故障处理和真实小任务观察 | 关键案例逐项通过，形成问题和修订记录 |
| 正式手机迁移 | 共用业务接入手机平台能力，核对资料与证据的版本和引用 | 业务行为一致，档案转移/恢复可检查，手机不依赖电脑服务 |
| 真机小范围试用 | 连续学习、移动专项、资料保护与效果观察 | 问题有记录、修正有依据，再决定扩大范围 |

不承诺尚未验证的开发日期和运行耗时。商业模式、团队具体分工、预算上限与发布渠道不是当前个人 MVP 的前置功能；若需用于三创赛正式申报，另补市场验证、竞品、商业路径与团队材料，不虚构用户量、收入或研究成果。
