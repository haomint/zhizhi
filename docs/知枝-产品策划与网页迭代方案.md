# 知枝：产品策划与网页迭代方案

版本：0.8｜建立及更新日期：2026-10-25｜阶段：第三版已接入自适应调研、分层路线和完整节点生成检查；真实模型教学质量待体验。

这是本轮梳理产品体验的独立策划案，随实装版本更新。原有策划案与专项文档作为历史参考，以本文为准。

## 1. 主体概念

### 1.1 产品是什么

知枝是一款围绕个人学习目标组织内容的学习助手。用户表达想了解或解决的问题，应用帮助确定合适的学习范围、组织路线、准备有依据的讲解，并以便于连续阅读的内容呈现。学习过程中，用户可以主动提问、改变讲法或调整方向；离开后能够继续，新的学习也能承接相关的既往经历。

产品希望让用户每一步都清楚：现在在做什么、为什么需要这一步、接下来可以做什么。路线、资料、生成任务、个人记录等能力，应当共同服务于这条学习过程。

### 1.2 预期内容与特点

产品内容与特点如下。

学习从自然表达开始。用户可以说清楚具体目标，也可以带着模糊兴趣进入；应用提取已经表达的信息，只补问影响下一步的必要缺口，允许不确定、多个兴趣以及主次侧重。

内容围绕目标形成主线。路线展示当前要学什么、前后怎样关联，并为后续调整保留空间。首次学习先准备一个能够完整讲清的小节，阅读过程中再按需准备后续内容。

讲解重视定义、白话解释、完整例子、必要条件和前后衔接。短卡片用于降低阅读负担，具体篇幅和分段服从内容完整性。不同学科采用适合自身的讲述结构。

用户掌握学习节奏。主线以阅读和主动问答为主，自愿加强作为独立入口；浏览过的内容和检查获得的证据分别记录。用户提出“例子不懂”“先讲定义”“需要更多基础”等要求时，后续相关内容应有可观察的变化。

资料与个人记录各有明确用途。外部资料为知识内容提供依据；个人记录帮助承接进度、相关经历与讲法偏好。来源、用户原话、助手提议与尚未确定的信息应能区分。

### 1.3 预期的完整体验

进入应用或继续上次学习 → 表达目标 → 必要补问 → 确认简短学习约定 → 查看路线 → 准备首个小节 → 连续阅读 → 按需提问或反馈 → 继续下一节或结束 → 保存进度与整理新增记录 → 下次继续。

资料管理、路线调整、知识树、自愿加强、个人记录和设置作为这条主线的相关入口，随对应环节逐步细化。

### 1.4 本轮开发范围：已确认

程序、手机端运行和 Pi 框架可行性已有用户验证，作为现有技术基础。当前工作转入完整体验的重新梳理与逐段完善。

本轮通过持续对谈积累需求，再制作方便修改的网页版供用户验收。当前不进行 APK 打包、安卓原生开发或移动端适配。已有工程和历史实现可以复用，具体改动围绕新确认的体验方案展开。

## 2. 开发指导

### 2.1 表述要求：已确认

正文用简洁的陈述句，直接写讨论后的结论。只写已经确定和已经完成的内容：做了什么、结果怎样、规则是什么。不写候选、待定这类过程状态，也不写“便于后续扩展”这类开发视角的说明。

### 2.2 协作与开发流程：已确认

按体验顺序逐段讨论，从开场和需求调研开始，覆盖操作、内容、反馈与衔接。累计需求形成一段可操作、可验收的体验后，制作对应网页版，由用户实际操作并反馈；暴露出的前序问题返回修改，开发顺序随实际体验调整。

### 2.3 策划案维护时点：已确认

大范围内容对谈完成、准备实装一版测试效果时，才修订策划案正文。新版本完成后同步一次，写入实际做出来的内容、确定的规则和验证结果。日常讨论只在对话中推进，不逐条改稿。

### 2.4 框架、模型与外部组件

现有工程采用 React、TypeScript、Vite 与 Capacitor，学习 Agent 基于 Pi Core，本轮复用其网页代码与业务能力。模型适配当前为 DeepSeek；最终模型与分工由同一批样本对比确定，比较指令遵循、数学与解释质量、结构化稳定性、上下文需求、耗时和成本。

网页版采用浏览器直连模型：用户在个人中心填入 Key，Key 存在本机，请求直接发往模型服务（已验证跨域可用），没有中间服务器。端点与模型名集中在一处配置，可换成其他兼容服务。未配置 Key 时进入演示模式，界面持续标注。

第一版只做一条最短链路：方向 → 路线骨架 → 单节卡片 → 阅读 → 继续。联网搜索、网页读取与来源原文核对不在本版。

内容生成第一版采用单 Agent 加联网搜索与网页读取工具，学习记录、卡片和资料来源保存在本地。资料按需检索：先取学习框架，再针对当前缺口找内容，核查后保存复用。WeKnora 在需要批量文档管理与跨文档检索时接入，第一版不引入。

### 2.5 开发关键点

界面使用学习者能理解的文字，当前主要操作突出；必要信息与可选设置分开。用户原话、重要输入、阅读位置和已保存内容及时保存。等待、失败、取消和重试都有能理解的状态与后续操作。

外部材料记录实际取得的内容与出处。模型生成、搜索结果、实际读取和经过核对属于不同状态。检索片段进入讲解前，检查上下文、公式、条件与支持范围；关键缺口不用虚构引用填补。

反馈作用于相关内容，调整目标或明显扩大范围时让用户选择。新生成结果提交前检查输入版本和目标位置，避免过时结果覆盖当前安排。既有个人记录只在相关且有依据时用于教学。

代码与文件以便于理解、修改和回退为原则。每批围绕已讨论的体验组织改动，不引入与当前流程无关的大规模重构。

### 2.6 网页验收与记录

每次网页交付使用一组能复现的输入和操作路径，说明本版覆盖哪些环节、哪些数据为演示、哪些功能调用真实能力。验证主要操作、状态变化、输入保留和必要的失败恢复；按改动影响执行工程检查与交互验证。验收不含 APK 和安卓专项。

用户验收关注“能否顺畅完成预期学习过程”。程序运行、内容质量与用户体验分别记录。

已交付：第二版网页，在首页与三步调研之后接入路线与节点：模型生成 4-6 节路线（标题、意图、前置、用时），点开任一节先看意图，再按节生成卡片，写完一张可读一张。失败保留已写卡片并给重试；生成只锁当前节点，其余操作不受影响。Key 在个人中心填写，存在本机。

原则与代码位置逐条对应，见[原则与实现对照](/workspace/知枝/outputs/网页原型/知枝-v2/原则与实现对照.md)。尚未接入联网搜索、网页读取、提问、知识树层级、加强、结算。

## 3. 每一部分的具体内容

按用户确认，本轮按四大功能模块组织开发：需求调研、内容准备、实际使用、UI 细节设计。前三个模块定业务与体验逻辑，第四模块统一打磨界面，制作网页版时同时提供必要界面。

### （1）需求调研

用户先自由表达想学的内容、用途、困惑或希望达到的程度。应用从表达中提取已知信息，避免让用户在填写表单时重复叙述。

只有当某个缺口会明显改变下一步安排时才补问。问题简短，每轮围绕一个主要问题，可以结合可点击选项与自由输入，接受多选、补充、主次侧重和不确定。基础经历与理解程度分开，不从“没做过”推断“完全不懂”。

当目的、范围和阶段成果已足以形成合理起点，就进入学习约定。暂时不知道的基础和可选偏好可以保留，并在学习中调整。具体开场、补问方式、何时结束以及“先体验”的路径，是下一轮优先讨论内容。

用简短摘要说明这次学什么、为什么学、先达到什么程度，以及重要范围或约束。应用提出的建议与用户明确表达的信息能被区分；未知项继续保留。

用户可以直接继续，也可以修改关键内容或返回补充。确认不要求逐个填写全部偏好。只想先看路线或试读时，应清楚表达当前仍是草案或体验安排。约定修改后，相关路线与后续准备采用新的有效版本。

### （2）内容准备

路线围绕当前目标给出主要节点、顺序和必要的前置关系，帮助用户知道为什么从这里开始、之后将走向哪里。远期节点可以先保留轮廓，再随实际学习细化。

用户能够辨认当前节点、必学与选学内容，并按需要查看节点用途或调整方向。重大目标或范围变化先展示具体建议，由用户选择。路线的展示密度、跳读方式和调整入口继续通过对谈确定。

资料可以来自用户提供的材料、预先整理的可信资源，以及针对具体缺口的联网补充。资料选择应与学科、课程版本和学习范围相符，保留原文与必要上下文。

流程需要明确资料从哪里进入、谁负责读取、哪些内容成功取得、能支持哪些知识点，以及读不到或出现冲突时怎么办。资料不足时可以补充、换材料、缩小节点或推迟非必要内容；核心缺口保留明确状态。

资料获取先走搜索与网页读取，再区分“找到入口”“取得正文”“核查通过”“支持本节内容”四种状态。搜索结果不直接进入卡片，读不到正文或公式不可靠时保留缺口，不用推测补足。

当前小节准备包括知识要点、依据、讲述顺序、正文和发布检查。节点需要能独立讲清，经过检查并保存后成为正式阅读内容。卡片标出重要度星级，表示对当前目标的关键程度；资料质量与用户掌握情况分别记录，不合并成一个分数。

用户提交后应立即看到已受理状态，知道正在准备什么；失败时能查看原因并采取下一步操作。取消或重试保留输入和已保存内容，不展示虚构进度。生成阶段的呈现方式与首次等待的可接受程度随真实体验讨论。

首节之后按需预备下一节点。储备规模根据连续阅读、反馈重写与实际等待调整，用户主动打开的内容和当前问题应有清楚的处理顺序。

节点可以先展开、后生成。点开未准备的节点，先给这一节讲什么、需要哪些前置、大概用时，这些来自节点任务，不等正文。未准备状态分四种：未开始、排队中、正在准备、准备失败。失败在原位说明原因并给重试，不弹回上一页。

生成按节点排队，锁只作用在相关节点上。阅读当前节点时可以准备下一节点，翻页、看其他节点、看知识树不受影响。演示内容直接标注“演示”，不用禁用按钮表达。

### （3）实际使用

阅读页突出当前小节、正文、位置和继续操作。每段内容围绕一个清楚的小目标推进，保留完整解释、例子和衔接。数学内容要检查公式、变量与条件，其他学科采用适合自身的呈现方式。

卡片正文之后给出一个完整例子和一句可带走的结论，来源可展开核对。底部三个操作：换个例子、补前置、继续；换例子与补前置只改当前卡片，不改写作规则。

用户可以连续阅读而不被强制提问或测试打断。资料、依据、讲法、路线和管理功能在需要时可访问，具体布局通过网页版验证。离开后保留学习树、小节和阅读位置。

知识树可以逐层展开：先看到章与节点清单，点开节点看到这一节的意图与前置，再进入正文。查看树不会触发跳转，也不会丢掉当前阅读位置。

页面上的忙碌状态按操作区分：正在准备某节时，只有该节的入口显示进行中，其余可正常操作。

用户能针对当前内容提问，也能表达太难、太简单、例子不熟悉或希望换一种讲法。问答关联发问时的内容与版本，翻页后到达的回答仍归属于原位置。

应用先处理当前问题，再决定是否影响后续内容。一次局部困难可先局部解决；明确的情境偏好或长期要求记录适用范围。反馈后需要能辨认采用了什么调整，效果不足时继续修订。

知识树呈现路线及学习经历，浏览、跳过和加强证据分别表达。用户可以按需要查看节点、回顾或进入独立加强。

加强围绕当前节点目标开展，题目应有可核对答案或判定依据。退出后回到原阅读位置，未通过保留原有浏览进度。通过结果关联具体目标和内容版本，避免把局部证据扩展成整门学科的掌握结论。入口、标记和判据后续单独细化。

用户可以结束本次学习，也可以暂停后回来继续。阅读位置和原始交流及时保存；需要模型参与的整理工作可独立处理，失败时保留待处理状态。

整理只处理新增记录，提取本次经历、明确反馈、未解决问题和有依据的讲解策略。没有新信息时不强行新增记忆，重复处理避免产生副本。主线不增加必须填写的总结问卷。

### （4）UI 细节设计

首页整屏铺满，底部三栏：首页、学习库、个人中心。首页中部是整宽的“创建新的学习内容”，下方“继续学习”列表按最近使用排序，每条显示主题、当前位置、进度和节数；整卡可点，直接回到原位置。

页面介绍、示例和引导的具体形式待讨论。引导在对应功能出现时提供解释，日常使用保留可随时查看的帮助入口。已有新手引导可作为素材，是否沿用以及触发方式随新页面重新确定。

用户回来后能够辨认上次学习的主题、节点和位置，并直接继续。已保存内容可正常读取，需要补做的生成或整理任务有对应状态，不抢走当前阅读位置。

新的内容准备只调用与当前目标相关的个人记录。旧经历可用于解释或衔接，理解程度仍依据真实证据。首页排序、多个目标之间的切换和长期未学习后的提示待讨论。

用户可以查看、纠正、删除自己的学习记录和偏好，理解哪些是明确表达、哪些是整理或推断。要求忘记的信息在后续调用与整理中持续失效。

导入、导出和恢复用于保护学习成果；操作前说明影响，失败保留原档案。公共教学资源与私人记录分别管理。具体入口、权限、导出范围和服务部署边界在相关体验确定时细化。

设置包含模型配置、可用性检查及必要偏好；向用户区分已配置、测试结果和当前请求情况。帮助围绕当前页面提供解释，是否自动出现及如何重播随体验确定。

网络失败、资料不可读、模型返回异常和保存失败，都应在对应位置说明并提供可执行的恢复方式。技术排查信息按需要展开，普通学习过程使用易理解的表达。

这些通用行为贯穿前述每个环节，随着实际网页反馈持续修订。

首页美术要求已确认：尽可能简洁，减少小字和说明，突出主要操作。2026-10-25 生成三版静态视觉稿：A“暖纸与苔绿”（浅色、衬线字与植物元素），B“留白与钴蓝”（黑白、蓝色主操作与醒目无衬线字），C“夜色与浅紫”（深色、侧栏与浅紫主操作）。三版均包含开始学习和继续学习入口，画面内的课程是示例。

美术方向定为“暖纸与苔绿”，并据此生成三个细化方向：A1“纸本书页”（暖纸纹理、宋体与细线）、A2“植物线描”（近白浅绿、无衬线字与植物轮廓）、A3“淡彩留白”（奶油白、柔和衬线字与少量水彩）。画面只保留少量文字与基础形状，导航、课程列表和功能布局不作为界面定稿。

视觉稿与提示词保存在[首页风格探索](/workspace/知枝/outputs/首页风格探索)。


## 2026-10-25：第三版内容基础实装（当前增量）

在原 `网页原型/知枝-v3` 目录升级，复用阅读与问答流程。调研按关键缺口补问，形成可编辑且带来源状态的学习约定；规划生成章与节，取消六节硬截断；小节先生成必要要点与页序，卡片数量随计划变化，整节检查后才发布。失败保留草稿，最多自动修订一次。明确的讲法反馈用于后续未读内容，过时任务不能覆盖新反馈。

旧学习及正文保留，新建学习走新流程；修改约定会建立新路线并保留原条目。实现与验收入口见 [第三版原则与实现对照](网页原型/知枝-v3/原则与实现对照.md)。本轮迁移相关规则与业务校验，未接入 Pi Core、联网资料链或服务器持续任务。测试使用模拟接口，真实模型内容质量仍需用户体验。
