## 2. 开场与补问

截图：[v3 开场](assets/v3-migration/v3-intake.png)、[v3 补问](assets/v3-migration/v3-question.png)、[React 开场](assets/v3-migration/react-intake.png)、[React 无 Key 中断](assets/v3-migration/react-no-key.png)。

| 编号 / 差异 | v3 怎么做 | React 现在怎么做 | 决定与归属 |
| --- | --- | --- | --- |
| I1 开场 | 可视区居中的单个“要学什么”输入框，底部继续 | 标题、说明、对话记录、自由描述框、“先记下这一段”和“整理需求”两按钮 | **搬**居中单框，允许一句话含主题、用途、时间或困惑；保留叙述原文；#17 |
| I2 补问控件 | 当前发布入口是四个按钮：三个选项 + “不确定，先跳过”；点击单选立即前进，**没有自由补充或多选** | 摘要表单内最多一个补问文本框，选项只是小字提示，不可点 | **改后搬**一轮一主要问题与可点击选项；按 #17 增加多选、自由输入和“不确定”，不能照搬 v3 单选限制 |
| I3 是否重复问 | 无论开场是否已说明，程序先固定问“你的基础如何”“你想学到什么程度”；有 Key 后才判断额外高影响补问，总数最多 8 | 模型整理后最多保留一道问题；没有已经实现的逐轮选择流程 | **不搬**固定必问两题；#17 从用户原话提取已知信息，只问影响下一步的缺口，不为凑题重复询问；补问上限作为保护措施由实现明确。“想学高数的极限，下周考试”不得再次追问已知考试用途和时间 |
| I4 基础与理解 | “没学过/学过基础/比较熟悉”合在一道基础题里，不能独立表述经验与理解 | “难度与起点”是一个偏好字段，也没有两种证据的独立呈现 | **改后搬**简短问答形式；按 #17 将做过的经历和理解程度区分，不把没做过推断为完全不懂 |
| I5 无 Key | 基础/目标选择 → 完成 → 演示路线 → 演示阅读，可按用户输入建演示条目 | 整理需求先保存文字，然后弹模型设置；网页 Key 禁用。只能另点按钮进入固定高数演示树 | **搬**可贯通的无 Key 演示链路并持续标注；#17。真实模型通道已有 #9 / [PR #12](https://github.com/haomint/zhizhi/pull/12)，不是 #17 重新实现的范围 |
| I6 返回、保存与失败 | 回答保存本机，刷新可续答；改早先答案会清掉依赖答案；额外补问失败允许重试或完成 | 已提交叙述保存到草稿；“返回继续补充”取消摘要。尚未提交的 `message` 是组件状态 | **搬**逐步保存、返回修改和必要失败恢复；#17。保存失败不能继续或发出依赖未保存回答的请求；不要把组件未提交文字当已保存 |

代码定位：[`Intake.tsx`](../outputs/learning-grove/src/ui/Intake.tsx)、[`service.ts`](../outputs/learning-grove/src/application/service.ts) 的 `draft_message/summarize`。v3 HTML 中旧的自由输入表单仍存在，但被最终 `IntakeFlow` 覆盖；本表以实际可操作入口为准。

## 3. 学习约定

截图：[v3 约定与路线](assets/v3-migration/v3-agreement-route.png)、[React 约定表单（固定夹具）](assets/v3-migration/react-agreement-fixture.png)。

| 编号 / 差异 | v3 怎么做 | React 现在怎么做 | 决定与归属 |
| --- | --- | --- | --- |
| A1 摘要与确认时点 | 补问后只显示“问好了/完成”；点击完成即接受约定、启动路线，路线顶部显示“这次这样学”的学习/基础/目标短摘要 | 先展示“确认这次学习约定”的长表单：主题、目标、五项偏好、补问和备注，再确认生成路线 | **改后搬**短摘要 + 主要继续操作；#17 要求用户在继续前能看到学什么、为什么、达到什么程度、范围/约束。**不搬**先接受再首次展示摘要的时序 |
| A2 信息来源与未知 | 内部有 `explicit/proposed/unknown`；最终简版只显示短摘要、查看回答和“未确定”，没有完整展示所有字段来源 | `IntakeResult.information` 可接收信息，但界面表单不展示来源；摘要内容未经来源区分直接可编辑 | **改后搬**保留原话、建议、未知的区分，并在摘要中可见；#17。不能把内部有字段写成用户已能看懂，也不能把助手建议存成“用户明确表达” |
| A3 修改与版本 | “查看/修改约定”重开调研；完成建立新条目，带 `sourceGoalId` 与递增 revision，原学习保留 | 创建前可改表单或返回；创建后“调整学习约定”更新目标和偏好、增加 `contract_version`，标记未读内容需更新，**不会自动重建章节路线** | **改后搬**修改后路线使用新有效约定、旧内容不丢；#17。由实现者明确版本失效范围，不仅修改摘要文字；重大路线变更仍需用户选择 |
| A4 可选偏好 | 当前单框流程的偏好主要来自额外问答，未问项可留未知 | 摘要阶段铺开五个可选偏好字段 | **搬**不强迫逐项填写、仅补必要信息的体验；#17。保留编辑关键内容能力，将非必要偏好收起 |

## 4. 路线与节点

截图：[v3 节点展开](assets/v3-migration/v3-node.png)、[React 知识树](assets/v3-migration/react-route.png)。

| 编号 / 差异 | v3 怎么做 | React 现在怎么做 | 决定与归属 |
| --- | --- | --- | --- |
| T1 章/节与当前节点 | 章可折叠，节可展开，有章价值、节数、阅读分钟、选学标记；节的准备状态可见，但当前阅读节点的强调不足 | `chapter` 作为每个按钮的小字，整条路线平铺；有 current 样式及已浏览/加强证据，没有按章折叠与必/选学信息 | **改后搬**章/节层次与概览；保留当前节点和学习证据区分，补齐必学/选学识别；#18 |
| T2 先看意图 | 点节标题仅展开用途、前置、范围、预计阅读时间；另点“准备并阅读”才准备/进入正文 | 点知识树按钮立即 `visit` 并切回阅读；未准备节仅有标题、description、“准备本节内容”等通用提示，契约无独立前置/用时字段 | **搬**先展开意图、后准备；#18，同步必要契约、校验和调用方。展开查看不能丢失当前阅读位置，也不应立即切换当前学习节 |
| T3 准备状态 | `idle/queued/running/failed`；显示“未开始/排队中/准备中/需处理”，准备好则显示卡数；特定失败可能显示未核验草稿 | 节点主要显示浏览状态，`ready` 是布尔值；任务弹窗另有排队、运行、失败、中断等状态 | **改后搬**节点原位四态，文字按 #18“未开始/排队中/正在准备/准备失败”；准备完成与已浏览分开，不以一个颜色/百分比合并 |
| T4 原位失败恢复 | 路线和阅读等待区给错误、已保留草稿、继续/重试入口 | 任务弹窗可看错误与重试，节点页仍多为通用准备面板；操作错误经 toast | **搬**失败节点原位原因与重试；#18，保留已经写入内容与输入。弹窗错误被挡住的通用问题已有 #20，不在 #18 重做全局提示方案 |
| T5 忙碌范围 | 按节点排队，准备时可回路线、打开其他节；阅读时预备下一节 | 服务层已有任务队列/后台预备；UI 的 `busy = pending > 0` 会禁用多个无关操作，不能由“有队列”推断已满足局部锁定 | **改后搬**只锁相关节的生成操作，其余节点、翻页、看树可用；#18。恢复与后台任务要分别验证 |
| T6 演示与内容发布 | 有演示说明；待准备节仍可走演示准备，正文明确是排版演示 | 固定高数树可读；部分生成/重写按钮因 `tree.demo` 禁用 | **改后搬**可理解的演示标注与可走通的节点流程；#18。**不搬**未核验草稿发布例外及降低现有质量/材料门槛，原因见 G5 |
| T7 查看路线与返回 | 阅读返回独立路线页，可逐章展开，再点节进入 | “查看知识树/返回阅读”在同一 Reader 内切换；当前卡片页保存在节点 | **搬**查看时不丢位置；#18 负责只展开查看、返回阅读；#19 负责卡片位置保存。浏览另一节不得被误记为已经读完 |

代码定位：[`Reader.tsx`](../outputs/learning-grove/src/ui/Reader.tsx) 的 `showRoute/openNode`、[`Dialogs.tsx`](../outputs/learning-grove/src/ui/Dialogs.tsx) 的 `Tasks`、[`contracts.ts`](../outputs/learning-grove/src/contracts.ts) 的 `RoadmapResult/LearningNode`、[`service.ts`](../outputs/learning-grove/src/application/service.ts) 的准备与任务提交。

## 5. 阅读卡片

截图：[v3 阅读](assets/v3-migration/v3-reader.png)、[React 阅读](assets/v3-migration/react-reader.png)。

| 编号 / 差异 | v3 怎么做 | React 现在怎么做 | 决定与归属 |
| --- | --- | --- | --- |
| R1 正文层次 | 标题、引导句、正文、完整例子、收束结论；支持基础 Markdown/强调；来源与本节检查默认折叠 | 卡片主体是 `kind/title/text/image`，正文以纯文本排版；没有固定的独立例子/一句结论区域 | **搬**正文 → 完整例子 → 一句结论；#19。保留旧 `text` 卡片可读，补结构时考虑旧数据，不能只改提示词或复制 v3 渲染代码 |
| R2 来源 | 卡片内“来源与核对”“本节要点与检查”；明确模型检查不等于外部核验 | 下方“内容依据”弹窗可看来源、版本及质量信息 | **改后搬**卡片附近可展开查看，复用已有依据；#19。**不搬**把模型生成或检查通过写成来源已被外部核验 |
| R3 主操作与换例子 | 实际底部为“上一张/换个例子/继续”；换例子只替换当前例子，有备选演示例子；无“补前置”按钮 | “上一页/页码圆点/下一页或读完继续”；可通过主动提问要求换例子，但没有专门的局部换例子动作 | **改后搬**主操作按 #19“换个例子/补前置/继续”，另保留可达的“上一张”。两种局部调整仅影响当前卡片；**补前置是本轮新增要求，v3 没有可直接搬的实现** |
