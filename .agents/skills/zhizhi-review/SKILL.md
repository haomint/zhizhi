# 知枝 Issue 验收核对

先读根目录 `AGENTS.md` 和 `REVIEW.md`。本 skill **只核对 Issue 验收条件**。通用 bug 查找交给 Codex GitHub 机器人；描述与改动范围、测试减少或跳过、常见密钥泄漏交给 PR Guard，不重复实现。

读取 PR、关联 Issue 的完整验收条件和相关证明；按需查看代码、测试日志和截图。记录 PR、base/head SHA、核对者、是否作者自查、轮次及上轮已审 head。无法访问 Issue 时标“缺证据”，不假称完成。

1. 保留验收条件原编号和含义，逐条写 **已做到 / 没做到 / 缺证据**。代码证明实现方式，执行结果证明命令或操作实际通过；作者写“已验证”不独立构成执行证据。
2. 每项附链接或 `文件:行号`、命令及结果、截图位置；区分模拟测试、演示、真实模型和人工操作，不相互替代。
3. 要求的行为未实现则写“没做到”；看似实现但缺运行或人工证明则写“缺证据”。缺证据本身不是代码 bug，不编造问题、结果或人工确认。
4. 链接当前提交的 `web`、`guard` 和机器人完成结果。启动反应、作者转述、旧提交结果不算当前版本已完成；无法确认对应提交时如实标为待确认。

第二轮起只核对新增改动影响的验收项，引用仍有效的旧证据；已报问题只记录处理结果。历史改写使证据失效时重新取证并说明。审查员每发一次意见算一轮，最多三轮，仍有实际问题则重新设计或拆小 PR；轮次由合并人核对。

按 `REVIEW.md` 输出中文报告，零问题明确写“没有发现问题”，分别标明机器人结论与项目核对。最后一段“给不懂代码的人看的总结”第一句写“能合并。”或“不能合并。”；缺依赖、当前提交检查/机器人完成结果或必要人工验收时，写“不能合并”及具体缺项和操作步骤。

可调用 `$zhizhi-review` 或明确要求 AI 读取本文件。先本地输出，只有用户已授权发布到该 PR 时才贴评论；本 skill 不自动修改代码、触发审查、批准或合并。接入说明见 `docs/PR审查与验收.md`。
